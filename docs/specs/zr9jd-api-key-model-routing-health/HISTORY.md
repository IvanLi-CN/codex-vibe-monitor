# API Key 上游按模型路由健康管理 演进历史（#zr9jd）

> 这里记录影响后续维护者理解主题的关键演进原因。

## Decision Trace

- 2026-07-24：将 API Key 上游动态路由健康从账号维度细化到精确请求模型；模型错误不再单独拖累同账号的其他模型。
- 2026-07-24：采用真实流量学习、七天固定记忆、现有 15–60 秒指数冷却和单模型手动恢复，不增加后台探测流量或历史回放。
- 2026-07-24：落地模型路由状态表、结构化模型事件、读取/reset API、候选降权与健康事件面板；页面级证据锁定为 mock-only `ui_demo`，组件交互由 Storybook 覆盖。
- 2026-07-25：审查收口统一模型错误分类，阻止 API Key 动态错误写入永久静态拒绝标签；补齐 sticky 复用冷却检查、WebSocket 多轮模型归属、并发时序保护与 retention dry-run 计数。
- 2026-07-25：全量测试发现并修复通用 4xx failover 回放重复写入首块响应体的问题；最终 Rust、Web、Storybook、构建与文档门禁均通过。
- 2026-07-25：按反馈将模型路由健康卡片统一为固定桌面列轨道并压缩间距；Storybook 增加 provider、只读与错误状态，组件证据改用稳定边界截取并覆盖移动端无溢出。
- 2026-07-25：继续收紧扩展信息布局，将失败摘要与失败次数、类型、最近失败合并为同一条对齐上下文带，移除重复摘要行，并补充 Storybook 断言。
- 2026-07-25：按移动端审计补齐字段描述列表语义、局部颜色对比度门禁与 44px 触控目标；桌面端继续保留紧凑按钮和固定列轨道。
- 2026-07-25：生产诊断确认账号级 502/503 事件可从关联尝试或调用还原请求模型；事件读取增加模型回填供数据关联，健康页不展示请求模型，改为明确说明账号级失败影响全部模型，或点名模型级故障的受影响模型；不根据单次事件推断其他模型状态。成功、信息、恢复和重置事件不声明当前故障影响，恢复和重置仍保留路由变更，避免误读影响边界或显示空路由变更。
- 2026-07-25：影响信息改为结构化字段，账号级展示影响范围与全部模型，模型级只展示影响范围与具体模型；移除自然语言影响句及无法由事件保证的其他模型状态。
- 2026-07-25：影响范围与受影响模型改用共享 Badge primitive 渲染为独立 CHIP，并保留描述列表语义与移动端换行能力。
- 2026-07-25：影响 CHIP 并入事件元信息行；桌面宽度足够时与事件类型、来源、错误码和时间同排，窄屏按容器宽度自然换行。
- 2026-07-25：Demo 健康事件改用产品已支持的 `call` 与 `sync_maintenance` 来源值，避免 `operator`、`maintenance_scheduler` 等未本地化内部枚举泄漏到界面。
- 2026-07-26：最近账号事件的动作、来源、原因、路由状态与优先级统一通过 I18N 字典展示；未知协议值不再原样泄漏，已本地化原因不再重复显示后端英文描述，Demo 与 Storybook 也改用正式事件协议值。
- 2026-07-26：模型路由健康卡的失败摘要改为本地化失败类型，不再显示后端英文诊断 message 或 `model_unavailable` 原始枚举。
- 2026-08-01：确认 API Key 临时上游失败不再具备可靠的账号级归因。具备精确模型的 5xx、429、逻辑过载与传输类失败改为仅更新该模型路由健康；缺失模型、413、其他非硬错误与后台同步临时失败仅保留诊断。历史账号状态自然过期，不做迁移。
- 2026-08-15：为 API Key 精确账号模型组合增加可选缓存命中保护。低于固定 3840-token 样本下限的流量不参与学习；严格低命中逐步收缩未来并行并在最低并行的第三次连续异常进入 15/30/60 秒缓存冷却。所有模型冷却到期统一为单探针，缓存探针须取得合格健康 usage 才恢复全部并行。
- 2026-08-16：将可观测边界从账号详情扩展到实况页“路由”页签。全局和账号历史均以真实尝试为粒度，按模型组织，保留重试和无关联状态事件；严格排除 OAuth 与主动探测。登录健康改为紧凑摘要，模型健康的 48 小时证据按需展开。
- 2026-08-19：账号成功恢复改为事务内解析精确 failure fence；新失败及其派生冷却截止时间保留同一毫秒精度，既有秒级同秒记录保守拒绝恢复。HTTP 与 WebSocket 缓存终态继续独立记录模型证据，但账号仍有 route failure 时不再广播全局 availability，避免错误唤醒等待请求。
- 2026-08-19：NoCandidate 审计在 queue 模式下补齐全部可选候选的模型容量冲突计数，同时保持等待首选账号的原语义；最早可用时间收窄到本次因模型冷却被排除的账号，避免无关路由触发提前重选。
- 2026-08-19：NoCandidate Storybook 证据改用非持久 locale 注入，隔离中英文、移动端和暗色场景，避免浏览顺序污染产品 locale storage。
- 2026-08-23：路由泳道、尝试记录和候选比较统一显示 API Key 当前 `display_name`；仅缺失时回退稳定编号。移除与该合同冲突的编号强制展示和模拟角色后缀，账号池分组仍不进入路由读模型。
- 2026-08-24：实时路由甘特图的结构布局与数据装饰分离。真实事件在动画帧内合并为既有时间轴文本和 SVG 装饰更新，保留稳定实例与横向滚动；仅日期标题结构变化才重建，图表取消内部纵向滚动，由模型组、泳道和展开记录自然撑开高度。长 API Key 名称在每个实时帧从完整名称重新测量并保留完整提示；展开记录按其固有高度预留任务空间，不再成为独立滚动区域。

## Key Reasons / Replacements

- 现有账号级冷却无法表达“一个模型不可用、其他模型仍可用”，因此新增模型状态边界并保留账号级故障作为独立层。
