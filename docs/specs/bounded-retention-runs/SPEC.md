# 有预算、可恢复的 Retention 运行与任务观测

## Context and Scope

本主题约束 `retention_archive` 的运行边界、会话派生维护以及管理页观测。归档保留策略、Verified Archive 证明和 raw 文件所有权继续由既有 retention 规范约束。

范围包括手动、启动、固定间隔和恢复触发的同一任务执行入口；归档导致的 Prompt 缓存会话统计刷新及孤儿会话清理；此任务的调度、进度、运行历史和性能摘要；积压存在时的自动归档追赶，以及最近 7 天的小时积压观测。公共观测函数的必要修复须验证其他调用者兼容性，不扩展为全部 Managed Task 的重新设计。

本主题不改变保留天数、归档格式、汇总定义或物化所有者的启用控制，不以提升吞吐为理由放宽删除安全、在线请求优先级或运行预算。归档行删除不承诺 SQLite 数据库文件立即缩小。

## Terms and Interfaces

- 归档核心、会话派生维护、运行积压快照、运行完成度、待归档调用积压、最长归档逾期时长、自动归档追赶和小时积压观测采用 [CONTEXT.md](../../../CONTEXT.md) 的定义。
- 业务调用行、上游尝试行、会话 key、归档批次、文件和字节分别计量。
- 管理接口：`/api/system/managed-tasks/retention_archive` 及现有运行控制接口。
- Prompt 缓存会话统计与物化控制继续使用既有产品接口和独立的物化任务所有者。

## Requirements

### REQ-BRR-001 — 统一任务边界

所有触发路径 MUST 使用相同的单实例、低优先级准入、暂停、预算、活跃会话保护和结果发布规则。禁用 MUST 在已提交的安全边界阻止新工作；错过的调度 occurrence 不得累积补跑。

### REQ-BRR-002 — 运行预算

单轮 MUST 从实际执行开始计入准入等待、SQL、文件处理和阶段切换，工作预算为 60 秒。预算耗尽 MUST 阻止新批次并保存安全检查点；已开始的提交只能在安全边界结束。耗尽后的收尾耗时 MUST 单独可观测，不得把 60 秒宣称为强制杀死事务的保证。

### REQ-BRR-003 — 真正有界的 Prompt 查询

统计刷新和孤儿检查的每个 Prompt 查询页 MUST 具有 2 秒执行预算，实际停止 SQLite 工作并确认回滚或连接释放。结果 LIMIT 不构成扫描预算，丢弃 future 不构成执行取消。单 key 的大量调用也 MUST 可分页推进，不得永久重复同一个超时全量聚合。

### REQ-BRR-004 — 归档正确性

归档、源数据转换、汇总证明和 raw 文件释放 MUST 保持既有原子发布及所有权契约。预算、暂停、异常和恢复不得跳过未证明的源行、丢失汇总、重复计数或释放仍被引用的文件；压缩、扫描及发布阶段必须具备可安全结束的边界。

### REQ-BRR-005 — 统计刷新解耦

源调用删除或变更 MUST 在同一业务事务中失效相关统计并持久化受影响 key。归档事务 MUST 不执行会话统计的历史聚合；已提交的队列由既有物化所有者消费，不能因该所有者禁用而强行绕过其控制。消费、再入队和新 mutation 并发时不得丢失刷新需求或发布不精确统计。

### REQ-BRR-006 — 独立孤儿游标

孤儿会话清理 MUST 使用持久化的候选扫描范围和游标，按检查过的候选推进，而非仅按删除结果推进。每页必须检查精确的 key 引用、conversation invoke-id 引用、活跃占用和已有保留规则。某页超时、压力拒绝或异常不得阻止归档核心继续；尾部完成后须允许后续扫描发现新候选。

### REQ-BRR-007 — 恢复与事实所有权

正确性检查点 MUST 与对应业务提交保持原子性并留在业务主库。任务观测 MUST 异步写入维护库；维护库丢失、堵塞或损坏不得增加同步主库写入。重启和中途失败必须幂等恢复，且不能以运维快照替代删除安全证明。

### REQ-BRR-008 — 完成度与阶段结果

运行 MUST 同时记录归档核心结果、各阶段结果和总体完成度。捕获范围全部结束为 `completed`；有业务进展但仍有积压、预算耗尽或可恢复阶段异常为 `partial`；无业务进展且仅因压力或准入让行为 `deferred`；致命错误使用既有 `failed` 状态并保留原因。没有进展但存在可恢复待办的结果也须明确为 `partial`，不得伪装为 `deferred`。

后台刷新继续完成时 MUST 不改写已结束运行的审计结果。新增完成度须作为兼容的可选字段发布，旧的成功/失败状态不能被直接替换为新枚举。

### REQ-BRR-009 — 同单位的进度

总量 MUST 来自本轮开始时观测的过期 invocation 积压，附带观察时间和范围。已完成 MUST 只计本轮成功提交、属于该范围的 invocation 行；其他阶段计数分别展示。观测无法覆盖本轮范围时总量和百分比保持未知；待办未结束时不得显示总体 100%。ETA 仅可基于有效且近期的同口径吞吐计算，否则为未知。

### REQ-BRR-010 — 可解释的检查点

任务 MUST 发布阶段、提交计数、检查点、等待原因、重试时间和观测新鲜度。页面读取必须使用已有快照和有界采样，不得执行积压全表 COUNT 或触发统计重建。运行中使用合并后的约 1 秒快照更新；等待心跳不得冒充业务进展。停止更新必须显示观测过期。

### REQ-BRR-011 — 完整运行历史

运行计时 MUST 在真正开始前创建，包含失败路径的实际耗时。运行明细须保存现有 summary 的完整计数及阶段耗时、写准入等待、预算收尾、延期或失败原因。主摘要使用可读标签；缺少历史证据不得回填为零或推测完成度。

### REQ-BRR-012 — 性能摘要准确性

任务性能查询 MUST 覆盖半开时间窗内与窗口相交的全部时间桶，包括当前未结束的小时桶。最新耗时来自最新有样本的桶；后续空桶不得覆盖它。没有覆盖、遥测缺失和真实零次运行必须可区分，性能聚合不能替代单次运行历史。

### REQ-BRR-013 — 有效调度

页面 MUST 显示实际有效调度及来源，区分默认运行间隔、管理员覆盖和内部恢复重试。默认小时运行与恢复资格必须可观测；禁用时没有下次执行。更改展示和默认值解析不得覆盖管理员既有配置，不得同时保留两个可并发执行同一任务的调度器。

### REQ-BRR-014 — 前向兼容

新增持久化游标、刷新代次或运行结果字段 MUST 使用有序、幂等、可观察的迁移。结构安装、运行时 DML 和历史工作恢复必须分离；不得在 readiness 中做历史全库回填。支持的旧状态须能升级；中断发布须可前向修复，回滚程序不得隐式逆向迁移或重写部署过的迁移。

### REQ-BRR-015 — 精确统计读契约

统计刷新未完成时 MUST 沿用 ADR 0021 的精确读契约，返回暂不可用，不展示过期值或零占位。页面须能显示刷新阶段、积压及禁用或等待原因；这种统计读状态不得阻止归档核心推进。

### REQ-BRR-016 — 有积压时自动追赶

任务启用且仍有待归档调用积压时 MUST 自动接续有界运行，不依赖管理员持续手动触发，也不等到下一次小时巡检才继续。每轮仍使用同一执行所有者、单实例边界和 60 秒工作预算；轮间让行，压力拒绝后按真实原因退避并自动恢复。禁用任务 MUST 在安全提交边界阻止后续追赶工作。

默认小时计划及管理员 interval/cron 覆盖 MUST 控制巡检机会，而非限制积压追赶只能在这些 occurrence 执行。清空积压后回到有效巡检计划；恢复不是补跑错过的 occurrence。页面 MUST 分别展示下次巡检与追赶状态/下一次重试资格；重试资格不得表述为保证的实际开始时间。

### REQ-BRR-017 — 固定存量的消化能力

在事先确定的代表普通在线负载的验收工作负载下，任务 MUST 在 24 小时内完成起点捕获的待归档调用固定存量，且持续归档能力须超过该负载下新增过期行的速率。捕获使用固定的 retention cutoff 与 source 身份上界；后续插入或新过期的行不能被误算为原固定存量，成果仅以 Verified Archive 发布及对应源行转换的成功提交计数。

该能力 MUST 在超过百万行、含单 key 倾斜、持续在线读写及其他实际后台竞争的环境中实测。对照使用相同种子、请求序列和资源配置；基线与候选分别重复三次，在线 p95/p99 取各次结果的中位数，候选不得劣于基线。单次提交几行、统计队列归零或短时吞吐外推不得替代固定存量实际归零的证据。

持续高压超出普通负载范围时仍 MUST 保留在线请求优先与删除安全，并明确显示压力、未达成的追赶目标及剩余积压，不得通过提高写优先级或扩大无界事务兑现目标。

### REQ-BRR-018 — 可推进且可解释的归档批次

任务 MUST 对后台资源竞争提供有界、公平的准入和恢复机会，同时尊重真实 SQLite 压力与 P1/交互写优先级。阶段轮转及批次调整须在后续微批次生效，不能让无业务进展的占用或反复尝试同一拒绝边界使归档无限饥饿。

等待与停止诊断 MUST 区分后台槽竞争、写协调器等待、SQLite busy/locked 或压力冷却、工作预算耗尽、禁用/关闭以及阶段异常；保存发生阶段、已有提交成果和下一次资格。不得把后台槽被占用统一宣称为 SQLite 锁压力。所有工作完成或停止路径均须可解释，不得以 `partial` 代替原因。

### REQ-BRR-019 — 独立且持久的小时观测

系统 MUST 在任务没有运行、被延期或被禁用时仍独立采集待归档调用积压，不以运行历史或陈旧 health 值冒充当前观测。每个成功观测的数量与最长归档逾期时长 MUST 来自同一数据库读快照、适用保留策略及采样时间；采集必须有界、尊重在线资源优先级，不能由页面请求触发无界扫描。

维护库 MUST 持久保存覆盖最近 7 天的 UTC 小时桶及每桶最后一次成功的准确观测，保留实际观测时间与适用策略。后续失败不能覆盖该小时较早的成功观测；整个小时没有成功观测、升级前无历史、维护库不可用或服务离线时 MUST 留缺口，不得补零、插值或从当前主库反推过去。任务禁用不停止采样；进程停止时不承诺采样。

### REQ-BRR-020 — 最长逾期与空积压口径

最长归档逾期时长 MUST 是观测时仍待归档的 invocation 超出其归档资格时点的最大时长，不是最老请求年龄或任务运行时长。资格时点必须复用现有 Asia/Shanghai 自然日 cutoff 与严格过期比较规则；不得简单用请求年龄减去固定天数的秒数替代自然日边界。

准确观测到空积压时，数量为 `0`，最长逾期为空并展示“无待归档记录”；未取得准确观测时，两项保持未知。历史观测保留当时的策略，不得随后续保留策略变化重新解释旧值；策略变化须可识别。

### REQ-BRR-021 — 最近 7 天的积压图表

任务详情页 MUST 在一张趋势区展示最近 7 天逐小时的待归档 invocation 条数与最长归档逾期时长，时间轴对齐，并区分条数与时长单位。查询按半开窗口返回所有相交 UTC 小时桶，包括当前未完成小时；时间标签沿用页面的 Asia/Shanghai 展示规则。

图表 MUST 展示实际观测时间、缺测及观测新鲜度，不以最后一次运行成果充当待处理量，不把缺测或过期值画成真实零值。上游尝试、会话统计刷新、孤儿清理和 raw 文件的积压须按各自单位分别展示；缺少准确测量时明确未知，不能加入主图 invocation 总量。新字段缺失的旧接口与升级初期不足 7 天的数据必须可正常展示。

## Verification

### VER-BRR-001

- covers: `REQ-BRR-001`, `REQ-BRR-002`, `REQ-BRR-013`
- 方法：同一 fixture 分别使用手动、启动、默认/覆盖调度和恢复触发；注入压力、禁用及重复触发。
- 通过条件：单实例且无补跑；60 秒后不准入新批次；实际预算收尾有记录；页面有效计划与真实调度一致，覆盖配置不被修改。

### VER-BRR-002

- covers: `REQ-BRR-003`, `REQ-BRR-005`
- 方法：大表、单 key 倾斜、并发重新入队及真实慢 SQLite 查询 fixture；检查 SQLite 中断后的连接和事务状态。
- 通过条件：每页能真正停止、释放锁并恢复；跨页聚合等于准确基准；新 mutation 不被旧消费清除；禁用物化所有者时归档继续且刷新待办可见。

### VER-BRR-003

- covers: `REQ-BRR-004`, `REQ-BRR-006`, `REQ-BRR-007`
- 方法：在文件准备、发布、检查点和孤儿删除边界分别注入退出或异常，并插入新引用、活跃占用及游标之前的新候选。
- 通过条件：保留策略、汇总和 archive 证明不变；不误删、不漏恢复；游标按已检查候选推进；主库正确性状态不依赖维护库；短锁和循环扫描允许在线请求继续。

### VER-BRR-004

- covers: `REQ-BRR-008`, `REQ-BRR-009`, `REQ-BRR-010`, `REQ-BRR-011`
- 方法：已完成、部分、仅压力延期、无进展可恢复异常、致命失败、空积压和缺失历史证据的接口/UI fixture。
- 通过条件：核心与总体结果独立；计量单位不混合；未结束不显示总体 100%；未知不显示零；阶段及等待原因完整，失败耗时真实，后台推进不改写历史。

### VER-BRR-005

- covers: `REQ-BRR-012`
- 方法：非整点 24 小时窗、整点边界、当前小时成功样本、后续空桶、无覆盖和真实零样本；同时检查其他公共性能查询调用者。
- 通过条件：每个相交桶都被计算一次，最新耗时不会被空值覆盖；单次运行历史与聚合的时间口径可解释。

### VER-BRR-006

- covers: `REQ-BRR-014`
- 方法：支持的旧版本状态、空库、重复启动、DDL 完成但业务续作未完成、错误发布留下的游标和跨页暂存统计。
- 通过条件：幂等识别既有迁移；ready 不扫描历史；旧未知字段仍未知；前向修复保留 archive 和队列事实；API 旧消费者仍可读取原有字段。

### VER-BRR-007

- covers: `REQ-BRR-015`
- 方法：归档提交后队列待处理、跨页统计正在重建、物化所有者禁用以及全部刷新完成的读取 fixture。
- 通过条件：未完成时统计暂不可用且原因可见；完成后恢复精确值；归档不等待统计读恢复。

### VER-BRR-008

- covers: `REQ-BRR-016`, `REQ-BRR-018`
- 方法：默认巡检、管理员 interval/cron 覆盖、手动与追赶同时到达、轮间禁用/重启、后台槽长期竞争、写协调器等待、SQLite 压力及预算耗尽的 fixture；记录各停止边界的真实原因。
- 通过条件：有积压时自动接续且单实例，每轮预算不变，轮间让行；压力解除后不等小时计划恢复；禁用阻止后续工作；自定义计划仅控制巡检且配置保留；空积压回到巡检；微批次调整实际生效，后台竞争不被误报为 SQLite 锁压力。

### VER-BRR-009

- covers: `REQ-BRR-017`, `REQ-BRR-018`
- 方法：shared-testbox 对开发基线和候选使用同种子百万行存量、单 key 倾斜、真实 archive 发布/文件路径及固定在线请求序列，包含实际后台任务竞争；分别重复三次，记录固定存量剩余量、新增过期速率、提交吞吐、准入/阶段耗时及在线 p95/p99。
- 通过条件：普通负载及资源配置在实验前固定并可复现；原捕获存量在每次候选实验的 24 小时内通过真实提交归零，持续处理量超过新增过期量；在线 p95/p99 中位数不劣于基线；正确性证明、60 秒边界、实际 SQL 停止及锁释放成立。超出普通负载的压力实验保留优先级并报告等待，不能被描述成已满足 24 小时目标。

当前证据状态：shared-testbox 已完成三轮候选和三轮基线的同 fixture 对照。候选固定 cohort 三次均归零，基线在三轮有界窗口内各提交 192 行并保留约 129.98 万行；候选在线读中位 p95/p99 为 67/90us，基线为 53/87us。吞吐与 24 小时目标已有实证支持，但候选尾延迟中位数略高，因此本条“在线 p95/p99 不劣于基线”仍保持未验证，不能据此宣称 VER-BRR-009 完成。

### VER-BRR-010

- covers: `REQ-BRR-019`, `REQ-BRR-020`
- 方法：任务停用/不运行、同小时多次成功后失败、整小时缺测、服务重启、维护库故障、预算中断、自然日午夜与正午记录、保留策略变化、空积压及并发插入/删除的采样 fixture，并与同一读快照的精确基准比较。
- 通过条件：数量和最长逾期来自同一次准确观测；停用仍采样；每桶保留最后成功值和真实时间，失败不抹除成功；空积压区别于未知，逾期符合 Shanghai 自然日首次过期时点；历史不回填、不重算，重启保留已持久化小时桶；采样取消后不留执行中 SQL 或锁。

### VER-BRR-011

- covers: `REQ-BRR-019`, `REQ-BRR-021`
- 方法：桌面和移动端 Demo/Storybook 及交互 fixture 展示下降/增长、零积压、缺测、过期、升级初期、统计待刷新、任务停用、自定义巡检和追赶重试；验证非整点 7 天查询与新字段缺失的旧响应。
- 通过条件：最近 7 天相交小时桶完整，两项指标时间轴一致、单位可辨、实际观测时间可读；不连接或补零缺口；其他阶段分别计量，未知不画为零；默认/覆盖巡检与追赶区别清楚，桌面和移动端满足视觉比较与交互契约。
