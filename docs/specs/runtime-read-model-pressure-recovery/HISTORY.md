# Runtime Read-Model Pressure Recovery - History

- The Initiative adopts an exact-read-model contract: Summary availability may not be obtained by returning partial, empty or request-time reconstructed data.
- Summary compact admission revealed that legacy failure classification was still reader-derived: payload-aware full aggregation and payload-free compact projection could disagree. The durable contract now requires one revisioned canonical classification, bounded live/archive compatibility materialization and shared reader consumption; raw diagnostics remain confined to that controlled background path.
- A bounded recent index records its first omitted live timestamp; rolling and account windows reaching that boundary fail closed while later fully retained windows continue from memory.
- The newest-N `current` view is isolated from rolling exact-boundary admission so dense historical boundaries do not abort unrelated current hydration; both resident views share one byte budget, and later runtime truncation preserves the newest omitted timestamp rather than relaxing an earlier durable boundary.
- Archive newest-N admission now uses bounded coverage-end proof: a potentially selected but unadmitted archive record fails only its affected scope closed. Historical persisted terminal coverage is likewise separated by global and account rollup proof, preserving global SSE de-duplication when only an account compact bucket lags.
- Global `current` archive admission is evaluated at the requested newest-N cutoff, while historical exact coverage requires both totals and scope usage proof. Current-only persisted terminals that can affect rolling repair are retained in the exact view, and both resident views reserve their shared byte budget before materialization.
- `current` source admission now fails closed when an unrepresented archive could fill a missing requested rank; it does not clamp that rank to the final resident record. Account current treats every incomplete completed archive as relevant until account representation is proven, and archive coverage endpoints include their newest persisted timestamp during hydration.
- Archive coverage distinguishes exact manifest endpoints for current admission from bucket-expanded rolling gaps. Materialized raw boundary replay gaps no longer discard complete durable-rollup interiors, while stale replay identities remain rejected and the materialized legacy marker stays narrowly compatible.
- Bounded archive coverage now uses the same exclusive endpoint for raw replay and compact-rollup proof; equal manifest endpoints remain single-row bounded coverage rather than legacy absence. Current candidate record admission failure is range-local so it cannot suppress an otherwise exact rollup-backed Projection.
- Summary SSE now rejects a cold projection from memory instead of rebuilding through the legacy SQLite path. A current-only archive candidate pruned from the newest-N index no longer pollutes the rolling omission boundary when matching global/account totals and usage rollups already prove that record's compact coverage.
- All-time raw replay now rejects stale SHA markers even when their archive path matches, for both global and account coverage. SummaryCurrent reads its immutable projection and terminal overlay atomically from hub state, and current admission recognizes an archive ending exactly at the selected cutoff as outside the half-open selected prefix.
- The Initiative records pressure defer as a scheduler state separate from an actual SQLite lock failure, so retry and audit behavior remain observable and bounded.
- Pressure defer keeps durable progress untouched because admission happens before SQLite; its eligibility deadline belongs to the in-memory scheduler, while a persisted real lock failure closes the pressure gate before releasing its permit.
- Coverage repair applies that same permit-scoped lock classification to its repair outcome and all following progress reads and writes, preserving one pressure record and the normal non-lock scheduler failure path.
- A retry-progress lock following a repair lock is one failed coverage attempt, so the persistence-error-first fallback records one pressure event while preserving the original-error fallback for non-pressure persistence failures.
- Coverage repair now returns every permit-scoped SQLite pressure error to the maintenance loop as a deferred outcome, preserving the in-memory pressure deadline and eligibility wake while suppressing task-run audit and generic retry writes; ordinary coverage errors remain visible as failed audited retries.
- The Initiative keeps long-term migration incremental and low priority, preserving durable cursor recovery and P1 writer priority.
- Checkpoint publication is intentionally separate from deployment; production observation is read-only and begins only after owner confirmation of the exact deployed release.
