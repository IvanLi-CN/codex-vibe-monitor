# Stats 长期用量与性能统计演进记录

## 关键决策

- 长期统计使用独立汇总表和独立 API，避免在现有 Stats 内容上叠加状态耦合。
- Normal terminal finalization is projection-cursor work, not a natural-day correction. Only mutations that revise an already persisted fact enqueue a bounded exact rebuild of the affected date.
- 日汇总永久保存，小时汇总保留默认 400 天且最少 366 天；所有清理动作以日汇总 materialized 为前置条件。
- 首次升级采用可恢复后台回填；回填未完成时只显示准备进度，避免把部分历史误报为完整结果。
- 完整汇总可以作为保留 continuity 的下界，但不能作为部分候选的更新来源；候选必须整体过滤后才能进入 UPSERT，避免被删除出重建集合的日期从 partial map 漏写。
- 历史 `overall` 日/小时与 canonical hourly rollup 不一致时，服务会从真实 live/archive 调用重建所有维度；canonical 的全量运营字段不能直接作为长期口径，只有排除 `running`/`pending` 的终态证明字段用于验证。有界增量写入会把证明降为未完成。每小时审计重新验证已完成 archive：当所有来源均可读时，完整扫描是可重建窗口中 canonical 桶的权威值，矛盾桶会被原子回写，来源已不含的陈旧桶会被删除，相关上海日期随即重建长期汇总并可替换为已验证空结果；全局来源下界之前故意退役的桶不参与删除。只有 archive 后续缺失或不可读、对账必需的源表/列缺失、或日/小时证明无法建立时，才撤销证明、持久化 repair queue 并进入 `error`，不能以剩余来源认证局部数据。证明协调错误未消除前，每一次后续刷新都立即重试完整对账，避免恢复后仍等待一小时。升级新增证明列时，源数据不完整的旧 canonical 行必须保持未证明，不能将默认零值当作空日。canonical 空日是合法的零值证明，且任一维度的非零残留都会触发清理，零总量跨日墙时续段则必须保留。归档删除时，来源安全下界由真实调用的最晚墙时终点精确计算，先随 `cleanup_state=delete_pending` 持久化在 manifest，只有文件删除成功或确认不存在后才在最终事务中推进全局下界；全局下界之前已认证的 canonical 桶是故意退役来源的历史证据，不能因不再出现在对账扫描中撤销证明。所有参与边界的调用与请求尝试匹配来源都必须能解析为有效终点，旧 archive 缺失可选 `invoke_id` 或来源时间列时按 `NULL` 兼容读取。canonical 终态证明重放也必须把缺失的可选调用字段（包括全部时间列）按 `NULL` 读取，并把缺失 `detail_level` 视为 `full`，不能因可读旧 schema 而永久撤销证明。归档继续保持 `completed` 可读，文件删除成功或确认不存在后才删除元数据，失败时留下可重试的删除意图。历史遗留调用 archive 若在本轮开始前已缺失且未进入 `delete_pending`，必须保留 manifest 作为持续来源丢失证据；来源对账会清除其长期 replay marker，使同身份恢复文件重新进入读取路径，且不从 manifest 猜测来源下界。请求尝试归档的账号映射无法追溯到可读调用来源时必须保留归档。调用归档暂时不可读时，不再猜测一个固定跨日窗口，而是阻断其开始日及后续候选发布、保留最后已知行并通过既有 `error` 合同重试。
- 删除意图不能只按 manifest ID 延续：月度归档可在文件替换时复用同一行。收尾因此比较完整归档身份，并在立即 SQLite 事务中复核文件 SHA-256；writer 在同一 `BEGIN IMMEDIATE` 区间内撤销旧 `delete_pending` 并替换文件，防止清理线程删除新文件。
- 来源证明也校验 completed archive 的 SHA-256，避免可读的就地篡改被认证。归档退役的安全边界以持久化候选累积，仅在没有仍保留来源跨越候选之前时才推进，防止长墙时调用或重叠 archive 把全局边界跳过可验证数据。
- 已物化调用 archive 如在可用性审计中确认丢失，会先使长期统计进入 `error` 并保留未阶段化 manifest；对账会撤销该 archive 的长期 replay marker，使来源恢复后可被重新读取。不可读 archive 缺失 `coverage_start` 时必须把整个保留窗口视为受影响范围，不能用 `coverage_end` 缩小候选阻断范围。
- 新增终态证明列的升级不能把旧 canonical 历史当作“完整空来源”：升级时把既有桶置于升级当天之前的迁移下界，保留其 operational aggregate 但不伪造新证明。迁移下界是持久化完成标记，不能只取决于本次是否执行了 `ALTER TABLE`，否则在最后一个列变更后中断会在下一次启动遗漏保护。调用 archive 清单与 live 调用也必须取自同一 SQLite 快照；retention 在两次扫描之间提交时宁可触发可重试的写冲突，也不能删除已有 canonical 桶。请求尝试 archive 若物理文件已经丢失且未进入 `delete_pending`，同样必须保留 manifest 作为 upstream 维度不可验证的证据。
- API Key 删除保留稳定统计身份，凭据、会话和路由状态全部清除；其它上游继续使用原删除行为。

## 关联演进

- 长周期归档与 retention 约束沿用 `9aucy` 的 materialization/cleanup 边界。
- 请求阶段耗时、模型与 cache 字段沿用 `z9h7v` 的可观测性事实源。

## 实现落点

- 长期统计读取路径只依赖日汇总；archive 仅在后台回填阶段解压读取，并通过 `long_term_usage_stats` replay target 阻止未完成 archive 清理。
- `LongTermStatsSection` 把长期统计状态隔离在现有 Stats 之后，模型/账号表格共享固定列定义并分别启用行、列虚拟化。

## 本次演进

- 用量图明确分成绝对值堆叠面积模式和既有折线模式；仅模型用量与上游账号图启用面积模式，其他长期图保持折线。
- 堆叠层序冻结为 overview 业务顺序，并改为以 `overview.daily` 的完整窗口生成连续自然日；缺失点与 `null` 均为零值，避免稀疏上游序列在图表中形成视觉断层，tooltip 总计与面积高度保持一致。
- 模型身份列统一复用性能表的模型图标/思考程度胶囊，并以固定总计行承载 `overview.global` 全量指标，避免搜索和虚拟滚动改变总计语义。
- 全局趋势的单序列不再使用与指标无关的“全部调用”名称；序列名是图例和默认 tooltip 的共同语义源，因此随 Token、成本、调用次数选择切换为相应总计标签。
- 长期多序列不能把产品图标或相近暖色当作唯一身份信息。完整模型名现在定义颜色家族，思考程度以名称、明暗和线型同时区分；上游账号使用独立的高区分度分类色板，避免排序或指标切换改变既有选择集合的视觉身份。
- 冻结身份列曾与绝对定位的指标虚拟列走不同的行内格式化路径，导致表头和总计视觉下沉；统一为块级 flex 行栅格后，纵向对齐与横向虚拟化保持独立。
- 图标已经提供模型身份时，重复的可见名称降低了密集表格扫描效率；恢复图标优先显示，完整模型名仅在悬浮和辅助文本中提供，未知模型仍保持文字可见。
- 同一图标优先合同扩展到长期图例：模型图标、思考程度与线型色标在同一居中对齐行内呈现，避免完整名称重复且图标基线下沉；tooltip 继续显示完整身份。
- 修复队列在加入跨午夜前置日期后，必须以最终替换范围读取请求尝试 archive；任何覆盖该范围的 completed attempt archive 缺失都代表不可验证来源，不能以空映射继续替换 upstream 维度，并且即使开始时长期状态为 `ready` 也必须切换为 `error`。
