# 独立性能遥测实现

## Runtime ownership

Rust 服务创建独立 SQLite pool 和单 writer；`AppState` 持有遥测运行时，关闭信号与服务生命周期绑定。遥测文件默认使用主库父目录下的独立文件，可由 `PERFORMANCE_DATABASE_PATH` 指定；`PERFORMANCE_TELEMETRY_ENABLED=false` 关闭采集。

## Storage

遥测库包含单一最终 schema 标记、进程 epoch、固定指标桶和 collector health。新文件一次创建完整结构，分钟桶按 UTC、分辨率、metric ID、静态 dimension code 唯一定位。固定桶直方图、计数/总和/最大值和固定采样周期产生的时间加权存量在事务中合并；schema 标记无法识别的文件直接标记为不可用并要求重建，不执行在线结构转换或数据清理。服务只保留 7 天分钟、30 天五分钟和 13 个月小时数据，并通过小批量清理及 WAL checkpoint 控制文件增长。

## Runtime integration

遥测只接入主库没有的系统运行状态：P1/P2 写入背压和 ACK、SQLite 锁与 WAL、读模型/SSE 发布、维护归档与 raw 文件量、进程资源、遥测自身健康和浏览器体验。代理请求的阶段耗时、结果、重试和字节数继续由主库调用明细承担，不再复制到遥测库。热路径只执行必要的原子更新或 `try_send`；采集库不可用时保留内存健康计数，不等待或重试主库工作。

当前代码注册 77 个指标 ID，展开为 104 条近期固定序列和 22 条长期序列。核心浏览器渲染时延按页面与设备档展开，长任务、资源请求、SSE、切入后台和能力不支持按页面族聚合；这样保留主库没有的诊断归因，同时减少请求热路径和指标库写入量。

逐项指标含义、单位、固定维度和留存层见[指标目录](METRICS.md)。该目录与代码注册表一起构成指标合同；研究文档中的未注册候选项不属于当前实现。

## HTTP and web

系统路由提供性能查询、独立健康和浏览器聚合上报。React 系统工作区提供时间范围、分层下钻和覆盖状态，按分层显示全部固定序列，并对耗时直方图显示 p95、样本数与未知桶；图表点数受服务端上限约束。服务端 HTTP 中间件只维护在途请求数，不按请求写入遥测事件；浏览器上报仅保留页面族和设备档等固定维度，同时记录同源 API/SSE 资源耗时和断开计数。

## Verification

数据库边界、单一 schema 初始化、滚动、跨保留层查询、限流和故障注入使用 Rust 测试；Web 使用类型检查、单元测试、构建和真实 Web Demo 视觉验证。共享测试机的低负载诊断、代表性 `overhead` 对照、50 ms mock 隔离复跑、30 天容量注入和写锁恢复记录在[经验性验收卡](empirical-candidate-card.md)。A6 的完整对照受共享测试机主库维护争用影响，禁用遥测基线在稳定窗口仍出现第三轮超时，因此 A6 作为发布后诊断项保留，不作为本次合并门禁，也不把差异归因于遥测。A7 复跑首次查询约 1.14 秒、写锁恢复后约 1.15 秒，健康探针失败 0 次、释放后丢弃 0 且 WAL 0，容量查询和故障隔离通过；此前一次 3.20 秒恢复查询作为偶发慢样本保留。
