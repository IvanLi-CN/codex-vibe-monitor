# ADR 0054：PR 元数据编辑使用单个完整 CI 证据门禁

## 状态

已接受；生产启用仍须通过真实 PR 门禁验收并取得合并授权。

## 背景

正文和标题编辑重复触发完整 CI。独立名称的 skipped job 可保留 CLI 中旧检查结果，但 PR #1321 的真实合并界面仍显示必需检查 Expected。原生轻量 job 重跑和受控 Checks API 失败探针均未恢复实际门禁。主人授权改为至多一个轻量 runner，保持仓库必需检查规则不变。

## 决定

保留全部原生检查名称。元数据编辑跳过 16 个重型 job，仅现有必需 Repository Tooling Checks 执行可信读取器。该门禁必须证明相同 PR、head/base 最近完整原生 CI 的全部 17 个 job 在同一完整 attempt 成功；任何较新失败、取消、未知证明、证据过期或部分重跑都阻断复用。失败传播由这个全局必需门禁承担，不再要求每个 skipped 检查单独保留旧失败。

轻量路径固定 runner、checkout 和执行步骤，拒绝候选环境及 shell defaults 注入；绝对路径的 Python 以隔离模式启动，避免 `sitecustomize` 等候选代码先行执行。读取器固定来自事件 base SHA，使用只读 Actions API；每次完整及元数据运行产生微型事件证明附件，区分调度路径并绑定身份。附件下载不携带 API token，证明保留七日。生产调度启用前先将读取器和格式兼容合同部署到 base；merge_group 继续使用 base 的可信合同校验器。

## 取舍与后果

每次元数据编辑增加一个轻量 runner，每次 CI 增加一个小型证明附件，换取完整构建和测试复用。完整 CI 进行中时轻量 runner 可能等待，合并门禁保持未完成。证据缺失时需要完整 CI，不能自动降级为跳过成功。API 显示的新 job ID 和 run_attempt 不足以识别完整重跑，还必须排除启动时间早于当前 attempt 的沿用 job。不同运行按最新 attempt 的启动时间排序，同秒歧义阻断复用；接受前重新核对 CI 快照，发现源 attempt 或运行集合变化则重新验证。

不采用人工成功检查重放或必需规则调整。兼容阶段生产调度不变；启用后的成功与失败路径都要在实际合并门禁验证，CLI 绿色不能替代该证据。回退到完整静态工作流即可恢复原验证路径。
