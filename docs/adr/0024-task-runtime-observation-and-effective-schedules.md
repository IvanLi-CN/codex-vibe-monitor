# Task Runtime Observation and Effective Schedules

Status: Accepted

任务目录采用独立运行区和可过滤的紧凑表格。运行区展示全部当前执行实例的任务名称、只读执行／让行级别、实际开始时间和执行用时，不受目录过滤影响；窄屏改为纵向条目。目录默认显示全部任务，启用状态使用全部／已启用／已停用，触发方式支持多选：同类选项取并集，与启用状态取交集。手动筛选表示手动专用任务，不把所有支持“立即运行”的任务归入手动类型。存在多个有效触发机制的任务可匹配相应多个选项。

当前执行的权威来源采用有界进程运行快照，由原 worker 与 managed dispatcher 在实际执行边界共同发布；任务运行历史、进度与运维自定义控制仍由维护库保存。开始时间在获得执行边界时记录，执行用时使用单调时钟，排队请求单独呈现。这样可以避免异步维护库写入延迟制造假运行状态，也能观察没有自定义调度的原 worker。快照只证明当前服务进程的执行状态；不能读取快照时显示观测未知。回填父子任务共享一个执行实例，在该实例下展示当前子任务，避免重复计数。

目录和详情区分运维自定义计划与只读生效策略，直接复用实际 worker 的常量、运行配置与策略来源；不把默认值补写为运维覆盖。显示明确的周期、UTC cron、自适应规则和策略来源，校正目录触发类型与真实行为的漂移。下次计划检查只显示调度器或 worker 能权威给出的时间，不承诺它是下一次实际执行时间。

计划编辑按任务的安全能力开放，并提供恢复默认。事件路径必须保留；定时兜底只有在已有安全支持时才能开放。已有自定义配置继续显示并保留，遇到能力不匹配时明确提示，允许显式恢复默认，不静默清除。手动和启动专用任务没有通用 interval／cron 编辑器。只读执行／让行级别来自真实资源规则，没有依据时为未定义，多阶段任务可说明不同规则，不新增统一任务优先级队列。

页面处于前台时每 2 秒刷新运行观测，包括无任务运行时；切回前台立即刷新，本地每秒更新执行用时。目录控制与详情观测在刷新时保持一致，自动刷新不覆盖未保存的计划输入。API 对现有目录响应增加生效策略、来源和能力信息，并通过独立运行观测接口提供有界快照，保持现有列表响应形状和历史字段含义。短于刷新周期的任务可能不出现在实时区，可在已有运行历史中查阅；历史覆盖不足时明确说明。

本决定补充 [ADR 0023](0023-task-operations-state-outside-main-database.md) 的观测边界：维护库继续拥有持久化运维数据，进程快照只证明当下执行状态。取舍是接受进程范围和短任务采样限制，换取真实开始／结束状态，并保持任务执行不等待观测持久化、不增加主库同步写入。历史旧记录缺少真实执行起点时保持未知，不将原入队时间改名为实际开始时间。

验收覆盖运行起止与入队区分、多任务与回填父子身份、资源让行、运行观测不可用、终态写入失败、默认与自定义计划、恢复默认、已有不匹配配置、组合过滤，以及桌面和窄屏可控 UI 证据。实现阶段遵循相应持久状态兼容与 API 变更门禁；本设计不将未核对的原 worker 批量迁移到 managed dispatcher。
