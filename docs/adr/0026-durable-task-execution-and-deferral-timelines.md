# Durable Task Execution and Deferral Timelines

Status: Accepted

任务运维总览采用最近 12 小时的紧凑多泳道执行时间图，并为任务让行状态保留一行共享时间轴的横条。泳道由执行重叠决定，色条与目录 Dot 使用固化在任务元数据中的标识色；当前等待同时包含实际已入队请求和独立的准入延后任务，两类等待分别命名并保留原有调度边界。后端接口仍支持最多 24 小时的窗口查询，持久化缓冲范围不随页面展示窗口缩短。

当前执行、dispatcher 队列、准入等待和时间线修订通过 SSE 快照与事件增量传输；不使用固定周期 HTTP 轮询。此传输决定取代 ADR 0024 中页面每两秒轮询运行快照的方案，同时保留进程快照对实时执行状态的权威性。浏览器在事件静默时每秒本地推进时间轴和有效开放时长，断线或数据过期后冻结外推并明确标为未知，恢复连接后用服务端快照校准。

后端在实际执行与让行观测边界持续产生有界记录，并异步保存在维护库；采集不依赖页面打开，已有区间在重启后可恢复。当前执行仍以进程运行快照为权威，历史记录通过同一执行身份关联，避免终态落库延迟制造假运行或重复色条。队列请求时间、实际执行起止和让行状态时间分别记录，旧记录缺少实际起点时不通过入队时间或含排队的旧耗时推算。

任务让行横条只描述影响任务准入或继续工作的压力与资源限制，保留原因和可确认的受影响任务。一般系统健康降级和聚合性能计数不是该行的状态或区间事实源；同一期间的多种限制保留原因集合。前端每秒推进滚动窗口与仍有效的开放区间，状态变化与结束结果来自后台观测。

本决定补充 [ADR 0023](0023-task-operations-state-outside-main-database.md) 的运维数据归属，以及 [ADR 0024](0024-task-runtime-observation-and-effective-schedules.md) 的当前执行边界。取舍是新增后台采集、异步持久化与覆盖诊断，获得页面关闭和重启后的历史连续性；浏览器采样、原有请求时间和累计指标不足以提供这些事实。运行路径不等待观测落库、不向业务主库同步补写，采集丢失、停机和旧记录不足均显式形成观测缺口。该总览不引入统一优先级队列，也不改变既有生产调度周期。
